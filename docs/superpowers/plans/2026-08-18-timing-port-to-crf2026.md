**Goal:** Re-home the timing module onto the crf-2026 codebase, replacing everything that duplicates crf-2026 prior work (penalties, laps/Rundenband, result paths, config, staff-area entry) with the established structures, while keeping the genuinely new capabilities (stations, append-only marks, offline capture boards, start sequences, WS live sync, hardware tokens).

## Binding integration rules (from the exploration reports — full details in .superpowers/sdd/progress.md)

1. **Penalties are display-only** (`competition_match_team.penalty_seconds/penalty_note`; "Nur ausgewiesen, nie verrechnet" — the measured time already contains the penalty). The timing module must NOT add penalties to times. DNS/DNF/DSQ = leading token in `failed_reason` (frontend/src/utils/matchResultStatus.ts convention, DQ→DSQ alias), NOT an enum column.
2. **No `timing_official_time` table.** Computed times (finish − start) are pushed via the SAME path as manual entry/RaceClocker: `timecode` record (id == team id, Parser.timecode round-trip — my Plan-4 parity logic is correct and stays), `failed`/`failed_reason`, optional `penalty_seconds`/`penalty_note` passthrough for display. Overrides = the existing manual-entry flow (CompetitionExecution dialog) — the Leitstand links there instead of duplicating an override editor. Dirty tracking: reuse `EventChangeMarker.bump(eventId)` conventions where applicable; a lightweight per-team dirty flag may live on a small `timing_result_state` helper table ONLY if nothing existing fits (implementer verifies first).
3. **Splits write laps:** an ACTIVE assigned mark on a SPLIT station upserts `competition_match_team_lap` (name = station name, lap_millis = mark − team's start, position = station sorting order; UPSERT on (team, position) preserving created_at — the Rundenband sort depends on it). Retract/unassign removes/corrects the lap row. This makes LapBand/boards/execution views work with internal timing unchanged.
4. **Sequence start integrates with match state:** when a start sequence fires a team's start mark (or a MASS start fires), set `competition_match.started_at`/`activated_at` idempotently (mirror `RaceClockerPollService`'s start-detection writes / `LiveDashboardService.markMatchStarted`) so LiveDashboard, stream clock (`useStreamClockDisplay`) and match state react identically to RaceClocker-detected starts.
5. **timingConfig owns the system choice:** extend `TimingSystem` enum with `READY2RACE`. The timing boards/stations are active for a competition/event when its (inherited) timing system is READY2RACE. RaceClocker module stays untouched as the proven fallback.
6. **Staff entry via App functions:** timing boards + Leitstand appear as App functions (like LIVE_DASHBOARD) in AppFunctionSelectPage / `qrApp/common.ts` (`APP_TIMING` privilege exists conceptually — re-add on this base). The separate "Posten" selection page from the old branch becomes the timing function's landing page (station select). Referee card: LIVE_DASHBOARD already exists — do NOT re-add a separate referee entry (drop old Task 5's approach).
7. **Leitstand scope shrinks:** Zeiten tab (cross-station marks, reassign/retract/delete-retracted) + Ergebnisse tab (compute + push + skip reasons + link into CompetitionExecution for overrides/penalties) + Geräte tab (hardware tokens). NO severity/finish/notes (LiveDashboard owns those). Push conflicts: frozen = `places_calculated || place != null || failed == true` (unchanged from Plan 4).
8. **Frontend naming collisions:** crf base has `frontend/src/utils/useServerClock.ts` (payload-driven). Port mine as `utils/timing/useTimingServerClock.ts` (or reuse theirs if adaptable — implementer decides after reading both; the timing one needs POST /timing/serverTime lowest-latency sampling, likely keep separate). Check ALL ported frontend files against existing names before writing.
9. **WS stays for timing surfaces only.** The ETag-polling infrastructure of the base remains untouched. AfterCommit/broadcast pattern ports as-is; also call `EventChangeMarker.bump` alongside broadcasts where base views should refresh (laps! match starts!) — verify how the base invalidates its ETag caches.
10. All Global Constraints from previous plans still apply (KIO/JOOQ/Flyway patterns, jooq regen via `./mvnw org.jooq:jooq-codegen-maven:generate -q`, tsp @operationId + surgical yaml merge — CHECK the crf base's documentation.yaml/tsp state first, it evolved independently; i18n de/en/da additive; commits English/imperative, no AI mentions).
